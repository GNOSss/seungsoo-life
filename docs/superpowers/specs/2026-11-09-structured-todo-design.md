# 구조화된 할 일/위시리스트 (diary_todo_items) 설계

- 상태: 승인됨 (브레인스토밍 완료, 2026-11-09)
- 관련 모듈: 일기장 (`/diary/notes`)
- 선행 작업: 헤더 메뉴에 "To Do" 추가

## 배경 / 문제

기존 `/diary/notes` 페이지(`diary_notes` 테이블)는 "할 것"/"하고 싶은 것" 각각을
마크다운 텍스트 블록 하나로 통째로 저장한다. 문제점:

- 항목 하나만 고쳐도 전체 textarea를 편집 모드로 열어야 함
- 타이핑 중 마크다운 소스가 그대로 보여 시인성이 떨어짐
- 날짜, 시간, 중요도 같은 구조화된 정보를 담을 수 없음(순수 텍스트)
- 개별 항목 체크/완료, 정렬, 필터링 불가능

사용자는 Notion 데이터베이스(표 형식)처럼 항목 단위로 다루고 싶어함.

## 목표

- 항목을 행(row) 단위로 관리 — 필드별 구조화, 개별 수정/삭제
- 날짜·시간이 있는 "스케줄형" 항목과 없는 "메모형" 항목을 한 리스트에서 자연스럽게 구분
- 모바일(아이폰 15 Pro Max 기준)에서도 시인성 좋은 레이아웃
- 기존 `diary_notes`(마크다운 블록) 데이터는 건드리지 않음 — 완전히 별도 신규 테이블로 시작

## 비범위 (Out of scope)

- 기존 `diary_notes` 마크다운 데이터의 자동 마이그레이션/파싱 (수동으로 새로 입력)
- 반복 일정(recurring) 기능
- 알림/푸시
- 완료 여부 추적 (`is_done`) — 브레인스토밍 중 제외 결정, 추후 필요 시 별도 ADR

## 데이터 모델

### 신규 테이블: `diary_todo_items`

| 컬럼 | 타입 | 제약 | 비고 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| user_id | uuid | FK auth.users, RLS 기준 | |
| kind | text | NOT NULL, CHECK IN ('todo','wish') | 할 것 / 하고 싶은 것 |
| importance | text | NOT NULL, CHECK IN ('high','mid','low'), DEFAULT 'mid' | |
| item_date | date | nullable | YYMMDD로 표시 |
| item_time | time | nullable | HH:MM로 표시 |
| target | text | nullable | 자유 텍스트 (예: "승수, 재나") |
| title | text | NOT NULL | 항목명, UI에서 Bold 표시 |
| detail | text | nullable | 상세보기 모달에서 편집하는 마크다운 본문 |
| sort_order | int | NOT NULL, DEFAULT 0 | 날짜 없는(메모형) 항목의 수동 정렬용 |
| created_at | timestamptz | DEFAULT now() | |
| updated_at | timestamptz | DEFAULT now() | |

**요일은 저장하지 않는다.** `item_date`가 있으면 클라이언트에서 요일(월~일)을 계산해서 표시한다.
`item_date`가 없으면 요일도 표시하지 않는다 (별도 입력 필드 없음).

### RLS

기존 패턴과 동일: `user_id = auth.uid()` 전체 CRUD 정책.

## 정렬 규칙

1. **스케줄 그룹** (`item_date IS NOT NULL`): 날짜 오름차순 → 시간 오름차순 (시간 없으면 그 날짜 그룹 맨 앞)
2. **메모 그룹** (`item_date IS NULL`): `sort_order` 오름차순 (신규 항목은 그룹 끝에 추가)
3. 스케줄 그룹이 메모 그룹보다 항상 위에 노출됨
4. `item_date`가 오늘보다 과거인 항목은 날짜를 빨간색으로 강조 표시 (지연 표시, 완료 추적은 없으므로 단순 시각 경고)

## 예외 처리

| 상황 | 처리 |
|---|---|
| 날짜만 있고 시간 없음 | 시간 칸 `—` 표시 |
| 날짜·시간 모두 없음 | 요일도 자동으로 `—`, 메모 그룹으로 분류 |
| `title` 미입력 | 저장 불가 (필수 필드), 그 외 전 필드 선택 |
| `item_date` 과거 + 날짜 있음 | 날짜 텍스트 빨간색 |
| `target` 비어있음 | 표/카드에서 해당 칸 생략 (빈 칸 아닌 완전 숨김) |

## UI — 데스크탑 (테이블)

```
[중요도] [날짜]   [요일] [시간]  [대상]      [항목]                [상세]
 🔴높음  251115    토    14:30   승수,재나   **미즈메디 병원 방문**   ⋯
 🟡중간   —         —     —      —          **거실 정리**            ⋯
```

- 컬럼 그리드: `중요도 56px · 날짜 72px · 요일 36px · 시간 56px · 대상 1fr(최소) · 항목 2fr · 상세 32px`
- 중요도: 색상 뱃지(빨강/노랑/초록), 클릭 시 높음→중간→낮음 순환 변경 (즉시 저장)
- 항목(title) 텍스트: Bold, 클릭하면 셀 단위 인라인 편집 (가계부 `TransactionAddRow` 패턴 재사용), Enter로 저장
- 날짜/시간/대상은 인라인에서 직접 수정하지 않고 상세보기 모달에서만 수정 (입력 부담 최소화)
- "상세 ⋯" 클릭 → 상세보기 모달 오픈

## UI — 모바일 (카드, 아이폰 15 Pro Max 430px 기준)

```
┌─────────────────────────────────┐
│ 🔴높음              11/15(토) 14:30│
│ **미즈메디 병원 방문**              │
│ 👤 승수, 재나                 상세 ⋯│
└─────────────────────────────────┘
┌─────────────────────────────────┐
│ 🟡중간                           │
│ **거실 정리**                 상세 ⋯│
└─────────────────────────────────┘
```

- 1행: 중요도 뱃지 (좌) + 날짜/요일/시간 (우, 있을 때만)
- 2행: 항목 텍스트 (Bold, 가장 큰 폰트)
- 3행: 대상(있을 때만, 좌) + "상세" 버튼(우)
- 날짜/시간 없는 메모형 카드는 1행이 뱃지만 남아 자연히 짧아짐 → 스케줄형/메모형이 카드 높이 차이로 한눈에 구분됨
- `md:` 브레이크포인트로 데스크탑 테이블 ↔ 모바일 카드 전환, 모바일은 가로 스크롤 없이 100% 폭 사용 (세로형 가계부/예산 모바일 레이아웃과 동일 원칙)

## 상세보기 모달

- 모바일: `vaul` 바텀시트 (프로젝트에 이미 사용 중인 라이브러리 재사용)
- 데스크탑: 중앙 모달
- 구성: 중요도/날짜/요일(읽기전용, 날짜에서 자동계산)/시간/대상/항목(제목) 입력 필드 전부 + `detail` 마크다운 편집 영역(기존 `NoteCard`와 동일한 textarea + `ReactMarkdown`/`remark-gfm` 렌더링)
- 저장은 "저장" 버튼 클릭 시에만 반영 (자동저장 아님, 실수 방지)
- "삭제" 버튼 모달 내부에 배치 (리스트에서 직접 삭제 불가 — 실수 방지)

## 인터랙션 — 추가

- 리스트 하단 "+ 새 항목" → 인라인 빈 행 생성, `title`만 입력 후 저장하면 바로 다음 빈 행으로 이어짐 (가계부 `TransactionAddRow` 연속 추가 패턴)
- 날짜/시간/대상/상세는 처음엔 비워두고 필요 시 상세보기 모달에서 채움
